# Scan Row Reconstruction (S-01) Implementation Plan

## Overview

Implement roadmap slice S-01: `cover-data inspect <image>` runs local OCR on a scanned debtor-list page, reconstructs the logical table rows, and shows them in the terminal with low-confidence OCR fragments flagged and geometric ambiguity surfaced. This is the project's north-star slice — it proves the assumption everything else rests on, that row/table geometry can be resolved correctly as data even when a scan is distorted.

Covers PRD FR-001 (point at an image file on disk), FR-002 (OCR with per-fragment confidence, low-confidence flagged), FR-003 (reconstruct logical table rows tolerant of misalignment), US-01's first half, and the NFR on temporary artifacts.

**This plan was rewritten on 2026-08-21** against the expanded fixture set (`90f8bf4`, `ef721c6`) and to carry the new multi-field search requirement. The original version was written against a six-fixture world and a ruling-line-primary geometry bet; both assumptions are now invalid. See "Current State Analysis" for what changed and why.

### Key Discoveries:

- **The "all fixtures have 8 data rows" assumption is dead.** `15.png` has 22, `18.png` has 26 (the table runs off the bottom edge mid-row), `19.png` has exactly 1, `20.png` has **0** (header only), `26.png` has 3 followed by a sign-off block, and `23.png` has **two tables on one page, both numbered from 1**. The previous plan's Phase 4 criterion "all six fixtures detect exactly 8 data rows plus 1 header" would fail on six fixtures and, worse, would be the wrong assertion to write.
- **`16.png` has no ruling lines at all** — `generate_edge_cases.py:1287` sets `block.grid = False`, and its manifest `must` reads "rows recovered from text clustering, not ruling lines." The previous plan made ruling lines the primary row-extent source and demoted text clustering to an independent cross-check. That is no longer tenable: the borderless path has to be a first-class strategy, not a fallback that gets the least testing while handling a supported fixture.
- **Ruling lines still earn their place where they exist.** They give row *extent* directly — the quantity `test-plan.md` Risks #1 and #2 turn on — and every fixture except `16.png` is ruled. The resolution is a per-document selector over two co-equal strategies, not a demotion of either.
- **The manifest carries content truth but not pixel geometry.** `ground_truth_rows` holds cell values only. `render_page` *does* compute the exact row and column edges (`generate_edge_cases.py:342`, `geometry_out["row_edges"]` / `["edges"]`) but in **pre-distortion, `SS=2`-supersampled space**, and only for the **last block rendered** — which is precisely wrong for `23.png`'s two tables. Nothing exports them.
- **The distortion chain is a mix of geometric and photometric operations.** Geometric: `wave`, `fold`, `rotate`, `perspective`, `fit_page`, `downsample`/`_finish`, and the canvas paste in `f26`. Photometric: `lighting`, `contrast`, `blur`, `noise`, `scanlines`, `jpegify`, `punch_holes`, `scanner_border`, `stamp`, `handwriting`, `initials`, `margin_signature`, `signoff_block`. Only the geometric subset moves a row edge — which is what makes exact geometry export tractable without analytically inverting a wave field.
- **Non-table ink is now a real, deliberate adversary.** Every generated fixture carries a margin signature; `22.png` adds a stamp, a biro annotation and punch holes; `25.png` lands an initialed signature *inside* row 5's address cell; `26.png` puts three stamps and three signatures below the table. These attack row detection directly and had no counterpart in the original six.
- **PESEL is not in the PRD.** FR-004 reads "matched against first and/or last name" (`context/foundation/prd.md:66`). Every generated fixture has a PESEL column. Adding PESEL as a searchable field is a contract change, not a plan detail.
- **Two existing search scenarios encode an open decision that `--field` resolves.** `8.png` declares `Kowalski` → 0 matches with the note "surname-only query is not an exact full-name match"; `21.png` declares `Wójcik` → 1 match because that row has no given name. Both were written assuming an unqualified query means full name. The chosen design — explicit `--field`, full-name default — keeps both scenarios valid as written and turns the open decision into a documented one.
- **The Paddle stack on 3.13 is verified, not assumed.** `uv pip compile` for `paddleocr[doc-parser]` + `paddlepaddle` at `--python-version 3.13 --python-platform windows` resolves to 97 packages including `paddlepaddle==3.3.1`, with `opencv-contrib-python`, `pypdfium2`, `pydantic`, `shapely`, `pyclipper`, `scipy`, and `pillow` arriving free and no `torch`.
- **The OCR engine decision is already locked** in `context/foundation/tech-stack.md`: PaddleOCR local, Python 3.13, develop-on-Paddle/ship-on-ONNX, engine behind a `Protocol`, weights pre-placed and never fetched at inference. That document explicitly states the pin, `.python-version`, CI, and `CLAUDE.md` are updated "as part of S-01". Not reopened here.
- **PP-Structure is excluded as a geometry source** by the same document — its table models self-report 59.5–69.7% on their own hard-table set and are trained on born-digital renders. Usable only as an optional disagreement signal.
- **Two upstream docs are stale.** `context/foundation/test-plan.md` §2 "Fixture set" describes six fixtures; its §3 Phase 1 lists change folder `context/changes/testing-fixture-foundation/`, which does not exist on disk. Both are corrected in Phase 1 here.

## Desired End State

`uv run cover-data inspect context/test_images/11.png` prints the reconstructed tables of that page — for each row, its `(table, row)` identity, its cell text keyed by **column role**, its pixel row extent, a flag on any fragment below the confidence threshold, and a flag on any geometric ambiguity detected. `--overlay out.png` writes a copy of the scan with the detected row and column bands drawn on it, so the geometry can be checked by eye. The source image is byte-identical afterwards, and no file other than an explicitly-requested overlay exists on disk when the command returns — on the success path, the failure path, or an interrupt.

Every reconstructed row on the twenty generated fixtures is attributed to the correct person — verified by best-match assignment against `manifest.json`'s `ground_truth_rows` resolving to the identity permutation — and the reconstructed row extents match the pixel geometry exported alongside them. Column roles — `lp`, `imie`, `nazwisko`, `imie_i_nazwisko`, `pesel`, `adres`, `kwota`, `wierzyciel` — are identified per document across layouts A, B and C, which is the typed contract S-02 builds `search --field` on.

Verified by: the full gate (`ruff`, `mypy --strict`, `pytest` including `slow`) green on Python 3.13; row extents and row attribution matching the manifest oracle on `7.png`–`26.png`; structural assertions holding on `1.png`–`6.png`; and a human confirming overlays sit on true row boundaries.

## What We're NOT Doing

- **No search command, matching, confirmation prompt, or preview** — FR-004 through FR-007 are S-02 (`person-search-confirm`). This slice makes search *possible* by identifying column roles as typed data and by recording the `--field` contract in the PRD; it does not implement a query. This boundary was reaffirmed during planning.
- **No redaction, no PDF output, no image writing beyond the optional overlay** — FR-008/FR-009 are S-03 (`selective-redaction-output`).
- **No PDF ingestion** — FR-001 scopes v1 to an image file already on disk; PDF is a named fast-follow (roadmap "Parked").
- **No PP-Structure / table-transformer / ML table-structure model** as a geometry source, per `tech-stack.md`.
- **No `img2table` or other third-party table-extraction library** — geometry is owned directly against OpenCV so per-fragment confidence retention and the coordinate contract stay under our control.
- **No ONNX export or PyInstaller work** — the develop-on-Paddle/ship-on-ONNX mitigation lands on `release.yml` and is out of scope until the pipeline is proven.
- **No testing of the OCR engine's own character accuracy** — `test-plan.md` §7 declares this deliberate negative space: "the engine is not ours to fix; the only thing we control is whether we flag what it is unsure about." This is why no assertion anywhere in this plan compares a recognized string to ground truth for equality. Content truth is used only to answer *which row did this text land in*, never *did the engine read it correctly* — see "Row attribution, not string equality" below.
- **No hand-labelled pixel ground truth for `1.png`–`6.png`** — superseded. Those six get structural assertions only; the generated twenty carry exact geometry instead, at lower cost and higher coverage.
- **No regeneration or retirement of `1.png`–`6.png`** — they stay in the set as the only non-script-generated samples, with their limitations recorded rather than papered over.
- **No `--json` output surface** — deliberately declined so the domain model can still change shape before S-02 couples to it.
- **No PESEL checksum gating** — decided during planning; see Phase 1.

## Implementation Approach

Seven phases, each independently committable and verifiable.

The **contract refresh** goes first and is doc-only. It amends PRD FR-004 to name the four searchable fields, records the `--field` and PESEL-normalization decisions in the roadmap's S-02 entry, and repairs two stale sections of `test-plan.md`. It leads because it defines what column roles Phase 5 must produce; building the column model first and retro-fitting the contract to it is how a plan ends up asserting its own implementation.

The **Python 3.13 migration** goes second and alone, so that it can be proven inert — gates green, no behavior change — before a 97-package dependency stack lands on top of it. A failure after a combined change would be ambiguous between the two causes.

**Fixture geometry export** goes third, before any geometry code exists. This ordering is the point: `test-plan.md` Risk #1's named anti-pattern is an oracle lifted from the implementation, and the only structural defence is to establish the oracle first. The mechanism is to push the already-computed row and column edges through the *geometric* subset of each fixture's distortion chain and record where they land — which yields exact, warped, code-independent geometry for twenty fixtures at a fraction of the cost of hand-labelling three.

The **domain model and OCR adapter** come fourth and establish two contracts the remaining phases obey. First: every coordinate the model carries is in **original, unresampled source-image pixels**. Document unwarping is a read-side aid only — its transform is inverted before any geometry is recorded, with a round-trip assertion proving it. Second: a row's identity is `(table index, row index)`, because `23.png` puts two tables on one page and both number their rows from 1.

**Geometry** then runs two co-equal strategies — a ruled path deriving row extent from horizontal rules, and a borderless path deriving it from text clustering — behind a per-document selector, with their disagreement retained as a signal wherever both are applicable. Column bands additionally carry a **role**, resolved from recognized header text, which is the enabling contract for S-02.

**Ambiguity signals** are computed from strategy disagreement and from intrinsic geometric checks, stored on the typed row model for S-02 to consume. The CLI surface lands last, once there is something real to display.

## Critical Implementation Details

**Row attribution, not string equality.** The content oracle exists to catch a fragment landing in the *wrong row* — the product's actual failure mode — not to grade the OCR engine, which `test-plan.md` §7 puts out of scope. So the assertion is a **best-match assignment**: for each reconstructed row, find the ground-truth row it most closely matches by string similarity across all its cells, and require the resulting assignment to be the identity permutation. A misread `ż` does not move the argmax; a swapped, shifted or dropped row does, and fails loudly.

Two consequences the implementer must honour. First, **normalization must not fold diacritics** — `9.png` exists to expose diacritic folding, and normalizing it away would silently cancel the fixture's entire purpose. Case and whitespace normalization only. Second, **`7.png` needs a tie-break rule**: it deliberately carries two rows both reading `Anna Nowak`, so those two must be compared as an unordered pair rather than a fixed order, or the check fails on an ambiguity the fixture was built to create. Within-row cell drift is not what this check catches; it surfaces instead as a cell-count mismatch and as a Phase 6 unassigned-fragment signal.

**The fixture generator has no clean geometric/photometric split, and three of its transforms are wrong for a mask.** Phase 3's geometry export depends on both, and getting either wrong yields ground truth that is *plausible but subtly biased* — the worst possible outcome, because every Phase 5 assertion then validates against a bad oracle and reports green. Verified against the source:

- **`fold` (`:379`) is both.** It applies the geometric pinch via `_remap` *and* multiplies in the crease shadow in the same function. It must be split before it can be treated as geometric.
- **`fit_page` (`:707`) derives its crop from image content** — `inked = np.where(arr.min(axis=1) < 200)`. A mask carrying only rule lines has different ink extent than a page carrying a title, table text and a signature, so recomputing the crop on the mask silently misaligns every exported coordinate. The mask must **inherit the page's crop box**, never recompute it.
- **`rotate` (`:396`) uses BICUBIC with `fillcolor=PAPER`, and `downsample` (`:703`) uses LANCZOS.** Both interpolate. A 1px mask line resampled bicubically and then Lanczos-downsampled by `SS=2` blurs into a biased position, and a bright `PAPER` fill reads as mask content. Every mask transform uses **NEAREST resampling and a zero fill**.

**Coordinate space is load-bearing and ordering-sensitive.** PaddleOCR's document-unwarping and orientation models resample pixels. Any geometry captured downstream of them is in *unwarped* space and will not address the right pixels in the source image. The inverse transform must be applied at the adapter boundary — before an `OcrFragment` is constructed — not deferred to a later consumer. Phase 4 asserts this by round-trip: a known point mapped forward then back must land within tolerance of itself.

**Row extent under waviness is a polyline, not a scalar.** `11.png` carries a 19px-amplitude horizontal wave and its `must` reads "band follows the wavy row boundary; no pixel of rows 3 or 5 survives, no pixel of row 4 is lost." A row boundary recorded as a single y-value cannot satisfy both halves of that sentence at once. Both the exported ground truth (Phase 3) and the reconstructed `RowBand` (Phase 5) must represent a boundary as a sampled curve across the page width. This is the single most consequential shape decision in the plan and it is nearly free at design time, expensive later.

**Vertical and horizontal line detection need different defences.** `6.png` carries full-height vertical scan streaks that pass every plausible "is this a long vertical line" test. Column detection must corroborate candidate vertical lines against the header row's cell structure or against detected text-column gaps, rather than trusting line length alone. Row detection from horizontal lines has a different adversary: `17.png`'s crease shadow band, whose `must` warns it "must not be read as a rule line."

**Two fixtures make row extent unbounded on one side.** `5.png`'s rightmost column runs off the page edge with no closing vertical rule; `18.png`'s table runs off the *bottom* edge mid-row, leaving row 23 with no bottom rule. In both cases the band must extend to the page edge rather than to detected content extent — a band computed from content stops short and would leave truncated text exposed in S-03. This is precisely the Risk #1 failure mode.

**Non-table ink must not move a boundary.** `25.png`'s in-cell signature and `22.png`'s stamp and biro annotation produce OCR fragments and dark pixels inside the table. A row-extent estimator that fits to ink extent rather than to rule position or text-baseline position will be dragged by them. Robust fitting is not optional here.

**The PaddleOCR result field names must be confirmed against the installed version.** The 3.x pipeline API (`PaddleOCR(...).predict()` returning `rec_texts` / `rec_scores` / polygon arrays, with `text_detection_model_dir`-style directory pinning) differs from the 2.x API (`.ocr()`, `det_model_dir`), and published documentation mixes the two. Confirm empirically at implementation time; the `Protocol` adapter is what confines this to one file.

## Phase 3: Fixture geometry export and manifest-driven harness

### Overview

Extend the fixture generator to export exact row and column geometry — warped through each fixture's own distortion chain — into `manifest.json`, and give tests typed access to the manifest as the single source of fixture truth. Written before any geometry code exists, so the oracle cannot be derived from the code it will judge.

### Changes Required:

#### 1. Geometry survives the distortion chain

**File**: `context/test_images/generate_edge_cases.py`

**Intent**: `render_page` already computes exact row and column edges (`:342`), but in pre-distortion `SS`-supersampled space, and every fixture then rotates, waves, creases, crops and downsamples the image out from under them. Carry those edges through the same geometric transforms so the exported numbers describe where the rules actually are in the final PNG.

**Contract**: The recommended mechanism is a companion **geometry mask** — a second single-channel image, the same size as the render, on which each row edge and each column edge is drawn as a distinctly-valued line — pushed through the *geometric* operations only (`wave`, `fold`, `rotate`, `perspective`, `fit_page`, `downsample`/`_finish`, and `f26`'s canvas paste), with photometric operations (`lighting`, `contrast`, `blur`, `noise`, `scanlines`, `jpegify`, `punch_holes`, `scanner_border`, `stamp`, `handwriting`, `initials`, `margin_signature`, `signoff_block`) applied to the page image alone. Edge positions are then recovered from the warped mask by nearest-neighbour sampling.

This is preferred over analytically composing the transforms because `wave`, `fold` and `perspective` are exactly the cases where an analytic inverse is easiest to get subtly wrong, and because the mask yields the warped boundary as a *curve* rather than forcing it back to a scalar. Whatever mechanism is chosen, threading it must not change any fixture's output bytes — the generator is documented as deterministic, and a diff in the PNGs means the geometric and photometric split was drawn in the wrong place.

**The mask contract** — see "Critical Implementation Details" for the evidence behind each clause, all of which is confirmed at the line level:

- `fold` is split into its geometric pinch and its photometric shade; only the pinch touches the mask.
- The mask **inherits the page image's crop box** from `fit_page` rather than recomputing it from its own ink.
- Every mask transform uses **NEAREST resampling and a zero fill** — never `rotate`'s BICUBIC/`PAPER` or `downsample`'s LANCZOS.
- `perspective` takes an explicit quad and is believed content-independent, but this is unverified — confirm it before relying on it.

Two structural fixes are required at the same time:

#### 4. Generator self-verification

**File**: `context/test_images/generate_edge_cases.py` (`verify`)

**Contract**: For each ruled generated fixture, sample **the pre-photometric render** — the geometric chain's output, which the mask mechanism already holds — along each exported row and column boundary, and assert the pixels there are ink rather than paper. Do **not** run this check against the final image: `24.png` applies `contrast(gain=0.55, offset=26)` then JPEG q30, so ink lands near 26 and paper compresses toward 161 and a fixed threshold is guesswork; `12.png` adds `scanner_border(level=32)`, so a boundary near the page edge sits on dark pixels and would **pass for the wrong reason** — a false green on the oracle itself. Keep only a loose relative-darkness sanity check on the final image.

## Phase 4: Typed domain model and OCR adapter

### Overview

Define the typed OCR-fragment model, the document/table/row hierarchy, and the swappable engine `Protocol`; implement the PaddleOCR adapter; and establish the coordinate contract that Phases 5–7 and both downstream slices depend on.

### Changes Required:

#### 1. Fragment model

**File**: `src/cover_data/domain.py` (new)

**Intent**: The typed structures `CLAUDE.md` mandates in place of dicts — a domain invariant, because an untyped dict makes a fragment → cell → row shape mismatch invisible until runtime.

**Contract**: `OcrFragment` carrying recognized text, a four-point polygon in original source-image pixels, an axis-aligned bounding box derived from it, the engine's confidence score, and a `low_confidence` flag. Frozen and immutable. Confidence is retained on every fragment regardless of the flag — flagging never filters, so a sub-threshold fragment still reaches the row model and the display.

#### 2. Document hierarchy and row identity

**File**: `src/cover_data/domain.py`

**Intent**: `23.png` puts two tables on one page, both numbered from 1, and its `must` states "row identity is (table, index)". A flat row list makes "row 1" ambiguous on that page and forces the repeated header to be filtered by heuristic rather than excluded by structure.

**Contract**: A `Document` holds an ordered sequence of `Table`s; each `Table` holds its header row, its ordered `TableRow`s, and its column schema. A single-table page is the ordinary case, not a special one — it is a `Document` with one `Table`.

**Two distinct things must not be conflated, and the manifest proves why.** A row's identity is `(table index, positional index)` — both owned by the model, both zero-based, both always present. That pair is what renders, what an ambiguity signal cites, and what S-02 resolves a match to. Separately, the **recognized `Lp.` value** is an ordinary cell value under the `lp` role, and it is none of those things: it is absent entirely in layout C, `None` on `21.png`'s blank row, and non-monotonic on `26.png`, a continuation page whose three rows read `6`, `7`, `8`. Deriving position from the page would break all three.

Manifest comparison therefore keys on **position**, and the three shapes of `ground_truth_rows[].index` map onto it as follows: `23.png`'s `'A1'`…`'B4'` — where the letter already encodes the table — maps to `(table 0, position 0)` through `(table 1, position 3)`; `21.png`'s `'1'`, `'2'`, `None` sequence maps to positions 0–7 with the `lp` cell carrying the literal value including its absence; `26.png`'s `'6'`, `'7'`, `'8'` maps to positions 0–2. S-02 will need the reverse translation to interpret `search_scenarios[].expected_rows`, whose entries are written in the same mixed form — note it in the roadmap rather than solving it here.

#### 3. Column roles

**File**: `src/cover_data/domain.py`

**Intent**: The enabling contract for S-02's `--field`. Column position differs across layouts A, B and C — `Imię` is column 2 in A and absent in B, where it is merged into `Imię i nazwisko` — so a role must be a named property of a column, not an index a consumer is expected to know.

**Contract**: An enumerated role covering `lp`, `imie`, `nazwisko`, `imie_i_nazwisko`, `pesel`, `adres`, `kwota`, `wierzyciel`, plus an explicit `unknown` for a header that does not resolve. `unknown` is a first-class value, not an error — a document whose header OCR fails still reconstructs rows, it just cannot be searched by that column. A `Table` exposes lookup by role; asking layout B for `imie` yields nothing, which is a correct answer and is what lets S-02 tell the user why a field-scoped query cannot run rather than silently returning zero matches.

#### 4. Engine protocol and adapter

**File**: `src/cover_data/ocr/engine.py`, `src/cover_data/ocr/paddle.py` (new)

**Intent**: Keep Paddle, a future ONNX runtime, and Tesseract swappable behind one interface, as `tech-stack.md` requires — this is what makes the develop-on-Paddle/ship-on-ONNX plan not a one-way door.

**Contract**: A `Protocol` with a single method taking an image path and returning a sequence of `OcrFragment`. The Paddle adapter constructs the pipeline once with explicitly pinned model directories and `lang="pl"`, and is the only module in the codebase that imports `paddleocr` or knows its result field names. Confirm those field names against the installed version — published docs mix the 3.x `predict()`/`rec_texts`/`rec_scores` API with the 2.x `.ocr()`/`det_model_dir` API.

#### 5. Coordinate contract

**File**: `src/cover_data/ocr/paddle.py`, `src/cover_data/geometry/transform.py` (new)

**Intent**: Every coordinate leaving the adapter is in original, unresampled source pixels. Document unwarping and orientation correction improve what OCR reads; they must never define the space geometry is recorded in, or S-03 will overwrite the wrong pixels.

**Contract**: The transform applied by any preprocessing step is captured and inverted before fragments are constructed. Expose the forward and inverse mapping as a small explicit type rather than leaving it implicit inside the adapter, so the round-trip is testable in isolation.

#### 6. Confidence threshold

**File**: `src/cover_data/ocr/engine.py`

**Intent**: Implement FR-002's flagging with a documented default that a caller can override.

**Contract**: A named default constant with its rationale recorded in a comment, overridden per-run by the value the CLI passes down in Phase 7. Tests drive flagging behavior by supplying threshold values as *input* rather than asserting against the constant — `test-plan.md` Risk #4 names the latter as an anti-pattern.

### Success Criteria:

#### Automated Verification:

- Unit tests construct synthetic fragments at chosen confidence levels and assert the flag is set correctly at, above, and below threshold, and that no fragment is ever dropped
- Round-trip test: a known point mapped through the preprocessing transform and back lands within tolerance of itself
- Role lookup on a synthetic layout-B table returns nothing for `imie` and a column for `imie_i_nazwisko`; on layout A the reverse
- Row identity is `(table index, positional index)` end to end — a synthetic two-table document distinguishes its two "row 1"s, and a row whose `lp` cell is absent, empty, or non-monotonic still holds its correct position
- A `slow`-marked test runs the real adapter over `7.png` and asserts fragments are returned with non-empty text, four-point polygons within image bounds, and confidences in the engine's documented range
- `uv run mypy src` passes under `strict = true`
- `uv run pytest -m 'not slow'` stays fast enough for the commit gate

## Phase 5: Row and column geometry — two strategies and a selector

### Overview

Build a ruled strategy and a borderless strategy as co-equal row-extent sources, select between them per document, resolve the column schema and its roles, and assemble cells into rows.

### Changes Required:

#### 1. Ruling-line extraction

**File**: `src/cover_data/geometry/lines.py` (new)

**Intent**: Find the table's horizontal and vertical rules — the strongest geometry signal, available on 25 of the 26 fixtures.

**Contract**: Separate horizontal and vertical extraction using morphological opening with long thin structuring elements, returning line segments in original pixel coordinates. Horizontal extraction is the ruled strategy's row-extent oracle. Two adversaries must be defended against explicitly: `6.png`'s full-height vertical scan streaks, which pass any length-based test and must be corroborated against the header row's cell structure or text-column gaps; and `17.png`'s crease shadow band, whose `must` warns it must not be read as a rule — a rule is thin and high-contrast, a shadow band is broad and soft, and the discriminator should be stated in the code rather than left to a threshold that happens to work.

#### 2. Ruled row strategy

**File**: `src/cover_data/geometry/rows_ruled.py` (new)

**Intent**: Turn consecutive horizontal rules into row extents, and separate header rows from data rows.

**Contract**: A `RowBand` type whose top and bottom boundaries are each a **sampled curve across the page width**, not a scalar — `11.png`'s wave makes a single y-value unable to bound the row correctly at both ends of the page. Consecutive rule pairs become bands; bands narrower than a page-relative minimum are merged or discarded as artifacts. Where no closing rule is found before the page edge — `18.png`'s bottom-truncated row 23, `5.png`'s right-truncated column — the band extends to the page edge, never to detected content extent.

#### 3. Borderless row strategy

**File**: `src/cover_data/geometry/rows_text.py` (new)

**Intent**: Recover rows from fragment positions alone. `16.png` has no rules at all, and its `must` states rows must be recovered "from text clustering, not ruling lines" — this is a supported fixture, so this path is a peer of the ruled one, not a degraded fallback.

**Contract**: Seed on the narrowest single-line column — the given-name or surname column, where horizontal span is short enough that wave and skew are negligible — then grow each row across the page using local-linearity extrapolation, fitting each row's baseline with a robust estimator so one stray fragment cannot drag it. Non-table ink is the reason robustness is required, not a nicety: `25.png` puts a signature inside a cell and `22.png` puts a stamp across rows. Enforce a global non-crossing constraint — fitted baselines must stay monotone across the page width. Row *extent* is derived by expanding each baseline to the midpoint of the gap to its neighbours, since no rule is available to give extent directly.

#### 4. Strategy selection

**File**: `src/cover_data/geometry/strategy.py` (new)

**Intent**: Choose per document, and preserve the cross-check value where both strategies apply.

**Contract**: Run rule extraction first; if a coherent horizontal rule set spanning the table is found, the ruled strategy owns the reported extents and the borderless strategy still runs as an independent second opinion whose disagreement becomes a Phase 6 signal. If no such rule set is found, the borderless strategy owns the extents alone and the document is recorded as borderless — a property of the result, visible to the user, not a silent internal branch. The borderless path must not consume the ruled path's output in either mode, or the independence that makes disagreement meaningful is lost.

#### 5. Column schema and role resolution

**File**: `src/cover_data/geometry/columns.py` (new)

**Intent**: Derive the column layout from each document rather than hardcoding one, and name each column's role — the enabling contract for S-02.

**Contract**: A `ColumnBand` sequence with left and right bounds, the header text recognized within each, and the resolved `ColumnRole` from Phase 4. Role resolution matches recognized header text against the known Polish header vocabulary, tolerant of OCR noise and of the multi-line header `Kwota / zadłużenia / (PLN)`; an unmatched header resolves to `unknown` rather than to a guess. A merged `Imię i nazwisko` versus split `Imię` / `Nazwisko` is a recorded property of the document, not an error. Where no closing vertical rule is found before the page edge, the final column extends to the page edge — `5.png` depends on this, and getting it wrong is precisely the Risk #1 failure.

#### 6. Multi-table segmentation

**File**: `src/cover_data/geometry/table.py` (new)

**Intent**: `23.png` carries two captioned tables with a vertical gap between them, each with its own header row. They must come out as two `Table`s.

**Contract**: Segment detected row bands into tables by vertical discontinuity and by repeated header structure — a band whose cell text matches the column headers starts a new table rather than counting as data. `20.png` (header, zero data rows) and `26.png` (three rows followed by a sign-off block of stamps and signatures) are the negative cases: a header alone yields a `Table` with zero rows, and the sign-off block yields no table at all because it has no column structure.

#### 7. Cell assignment and row assembly

**File**: `src/cover_data/geometry/table.py`, `src/cover_data/domain.py`

**Intent**: Place each `OcrFragment` into the cell whose row band and column band contain it, and assemble cells into rows.

**Contract**: `Cell` carries its column band (and therefore its role), its row index, the fragments it contains, and their joined text. A cell holds multiple fragments — the two-line address is the normal case and `14.png` wraps rows to three and four lines — so cell text joins fragments in reading order rather than assuming one per cell. A fragment falling outside every band is retained as unassigned, not dropped, and becomes a Phase 6 signal; this is how the margin signature present on every generated fixture is accounted for rather than silently discarded. A blank cell yields an empty `Cell`, never a missing one — `21.png`'s blank row 6 must not collapse the row index.

### Success Criteria:

#### Automated Verification:

- `slow`-marked: reconstructed row extents match the Phase 3 exported geometry on all 20 generated fixtures, asserting **top and bottom boundaries together** — never separately, since `test-plan.md` Risk #2 warns that separately-satisfiable assertions let the fix for one silently break the other. Tolerance is expressed as a fraction of *that fixture's own median row height*, not an absolute pixel count — the set spans 760px to 1240px wide with row pitches from ~24px (`15.png`) to full-size, and one absolute number cannot serve both. Start at 0.15 of median row height and record any change with its reason

## Phase 6: Ambiguity signals

### Overview

Compute the geometric, structural and cross-check ambiguity signals and store them on the typed row model. S-01 detects and surfaces; S-02 gates on them via FR-006.

### Changes Required:

#### 1. Signal types

**File**: `src/cover_data/domain.py`

**Intent**: Make ambiguity a first-class, typed property rather than a log line, so S-02 can consume it without re-deriving geometry.

**Contract**: An enumerated signal kind plus a collection of detected signals carrying the kind and a short human-readable detail. Signals attach at the level they describe — a row-level signal on `TableRow`, a document-level signal (a second table found, a borderless document) on `Document`. A row with no signals carries an empty collection, never `None`.

#### 2. Detectors

**File**: `src/cover_data/geometry/ambiguity.py` (new)

**Intent**: Implement the checks as pure functions over the assembled document. Each reports; none corrects.

**Contract**: Row-level detectors for — cell count differing from the document's own detected column count; row-band boundaries crossing or non-monotone across the page width; row height beyond N·MAD of the page median; the borderless strategy's row membership disagreeing with the ruled strategy's where both ran; any low-confidence fragment inside the row; any unassigned fragment falling within the row's vertical extent (`22.png`, `25.png`); and a row band clipped by the page edge (`18.png`).

Document-level detectors for — more than one table found (`23.png`); zero data rows found (`20.png`); the document reconstructed by the borderless strategy alone (`16.png`); and any column resolving to the `unknown` role, which is what tells S-02 a field-scoped query cannot run on this page.

Each detector is independent and none mutates the document it inspects.

## Testing Strategy

The fixture set is tiered by what each generation can actually prove, and every assertion is written at the tier its evidence supports:

| Tier | Fixtures | Assertions available |
| --- | --- | --- |
| Generated | `7.png`–`26.png` | Row extent vs exported geometry; row **attribution** vs `ground_truth_rows` by best-match permutation; row and table counts; column roles; search scenarios (consumed by S-02) |
| Original | `1.png`–`6.png` | Structural only — a table is found, column roles resolve, rows are non-overlapping and monotone. No extent or content truth exists, and none is invented |

No assertion at either tier compares a recognized string to ground truth for equality. That would be an OCR character-accuracy test, which `test-plan.md` §7 excludes.

### Unit Tests:

- Confidence flagging over synthetic fragments at, above, and below threshold; flag never filters
- Coordinate round-trip through the preprocessing transform
- Column-role lookup across synthetic layout A/B/C schemas, including the `unknown` case
- Row identity across a synthetic two-table document
- Cell assembly with multiple fragments per cell (the two-line address, and the three-to-four-line wrap `14.png` renders)
- Blank-cell handling — an empty cell exists and does not collapse the row index
- Each ambiguity detector in isolation, on a synthetic document it should fire on and one it should not
- Terminal rendering as a pure function of a synthetic document model, no OCR involved

### Integration Tests:

- `slow`-marked, over the 20 generated fixtures: row extents vs exported geometry with both boundaries asserted **together**, and row attribution vs `ground_truth_rows` by best-match permutation compared by column role
- Degenerate-shape pass: `20.png` (0 rows), `19.png` (1 row), `26.png` (3 rows plus sign-off), `23.png` (two tables), `15.png` (22), `18.png` (26, clipped)
- Strategy pass: `16.png` reconstructed borderless; the ruled fixtures reconstructed ruled with the borderless second opinion agreeing
- Edge-bound pass: `5.png` right column and `18.png` bottom row both bounded at the page edge
- Adversary pass: `6.png` vertical streaks rejected from the column schema; `17.png` crease shadow not read as a rule; `22.png` and `25.png` non-table ink not moving a boundary
- Structural pass over `1.png`–`6.png`
- CLI-level: exit codes, output shape, overlay written only on request, no stray files, source unmodified

### Manual Testing Steps:

1. Run `inspect --overlay` on `11.png`, `13.png`, `16.png`, `17.png`, `18.png`, `23.png` and confirm bands sit on true boundaries
2. Inspect recognized Polish text on `9.png` for diacritic correctness, and PESEL digits on a layout-A fixture against the manifest
3. Confirm column roles are correct on one fixture from each of layouts A, B and C
4. Confirm ambiguity signals are plausible rather than firing on every row
5. Confirm the working tree carries no stray artifacts and the fixtures are unmodified (`git status` clean)

## Performance Considerations

No latency budget applies — this is a single-user CLI run interactively on one page at a time, and a few seconds of OCR is acceptable. The real constraint is the commit gate: `lefthook.yml` runs `pytest -m 'not slow'`, so every test that loads a fixture through the OCR engine must carry `@pytest.mark.slow`. The marker is already registered in `pyproject.toml` for exactly this purpose.

The fixture count is now 26 rather than 6, and the full suite OCRs most of them. Keep the Paddle pipeline construction at session scope rather than per-test — model loading, not inference, dominates — and OCR each fixture once per session, sharing the result across the assertions that need it. Without that, the `slow` suite grows to a length that discourages running it, which is its own correctness risk. `18.png` (26 rows, ~1 MB) and `15.png` (22 rows) are the heaviest.

## Migration Notes

The Python 3.14 → 3.13 move requires contributors to have 3.13 available; `uv` will fetch it. After pulling Phase 2, `.venv/` must be recreated — `uv sync --locked` handles this, but a stale 3.14 venv will produce confusing failures. `models/` is git-ignored and must be provisioned locally before any OCR test runs; document the provisioning step in `CLAUDE.md` so a fresh clone has a path forward. CI is unaffected by the version move itself, since both workflows read `.python-version` rather than pinning inline.

Phase 3 rewrites `manifest.json` through the generator. The additions are additive and no existing key changes shape, but the regenerated PNGs must be byte-identical — a diff there means the geometric/photometric split in the distortion chain was drawn in the wrong place, and it is the first thing to check if fixtures show as modified.
