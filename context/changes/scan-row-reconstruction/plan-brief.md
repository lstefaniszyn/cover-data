# Scan Row Reconstruction (S-01) — Plan Brief

> Full plan: `context/changes/scan-row-reconstruction/plan.md`
> Research: `context/changes/scan-row-reconstruction/research.md`
> Rewritten `2026-08-21` against the expanded 26-fixture set and the multi-field search requirement.

## What & Why

Build `cover-data inspect <image>`: run local OCR on a scanned debtor-list page, reconstruct the logical table rows, and show them with low-confidence fragments and geometric ambiguity flagged. This is the roadmap's north-star slice — it tests the assumption the whole product rests on, that row geometry can be resolved correctly as data even when the scan is distorted. If it fails, no later guardrail matters, because rows would already be attributed to the wrong person.

This revision also carries a new requirement: the user will be able to search by `Imię`, `Nazwisko`, `Imię i nazwisko`, or `PESEL`. S-01 does not implement search — it makes it possible, by identifying each column's **role** as typed data and by amending the PRD contract S-02 will build against.

## Starting Point

`inspect` is a zero-argument stub that exits 1 (`src/cover_data/cli.py:37`). The only runtime dependency is Typer; no OCR, image, or geometry code exists. `tech-stack.md` has locked the OCR engine (PaddleOCR, local, Python 3.13) but the pin has not moved — the codebase is still on 3.14.

The fixture set has changed substantially since this plan was first written. `context/test_images/` now holds **26 fixtures** indexed by an authoritative `manifest.json`, in two generations: `1.png`–`6.png` from an image model with no ground truth and no PESEL column, and `7.png`–`26.png` generated by `generate_edge_cases.py` with **exact-by-construction row content** and 24 declared search scenarios. Three column layouts (A/B/C) are named and fixed.

## Desired End State

`inspect context/test_images/11.png` prints the page's reconstructed tables — each row with its `(table, row)` identity, its cell text keyed by column role, its pixel extent, and flags for low confidence and ambiguity. `--overlay out.png` draws the detected bands on a copy of the scan, following the wave rather than cutting across it. Row content matches `ground_truth_rows` and row extents match exported pixel geometry across all twenty generated fixtures. The source image is byte-identical afterwards, and nothing but a requested overlay ever reaches disk — on success, on failure, or on interrupt.

## Scope

**In scope:** PRD/roadmap/test-plan contract refresh including PESEL and `--field`; Python 3.13 migration; PaddleOCR stack with pre-placed offline weights; exported pixel geometry for the 20 generated fixtures; typed `OcrFragment` / `Cell` / `TableRow` / `Table` / `Document` model with column roles, behind an engine `Protocol`; ruled and borderless row strategies with a selector; multi-table segmentation; ambiguity detectors; `inspect` CLI with terminal display and optional overlay.

**Out of scope:** the `search` command itself and confirmation/preview (S-02); redaction and PDF output (S-03); PDF ingestion; PP-Structure or any ML table-structure model; `img2table`; ONNX export and PyInstaller work; OCR character-accuracy testing (`test-plan.md` §7); `--json` output; hand-labelled pixel truth for `1.png`–`6.png`; PESEL checksum gating.

## Architecture / Approach

```
image path
  → OCR adapter (Paddle, behind Protocol)  → OcrFragment[]  ── original pixels, transform inverted
  → rule extraction (OpenCV)   ─┬→ ruled row strategy      → RowBand[] (boundaries as curves)
                                └→ borderless row strategy → second hypothesis / sole source
  → selector (ruled if a coherent rule set spans the table, else borderless)
  → column bands + role resolution from header text (lp / imie / nazwisko /
    imie_i_nazwisko / pesel / adres / kwota / wierzyciel / unknown)
  → multi-table segmentation → Document[Table[TableRow[Cell]]]
  → ambiguity detectors (row-level and document-level)
  → rich terminal display + optional overlay PNG
```

The engine sits behind a `Protocol` so Paddle, a future ONNX runtime, and Tesseract stay swappable. The borderless strategy never consumes the ruled strategy's output — that independence is what makes their disagreement a useful signal.

## Open Risks & Assumptions

- **The fixtures are synthetic.** PRD Open Question #1 remains open — neither an image model nor a Pillow script reproduces ink bleed, print degradation, or real scanner optics. A green suite here is necessary, not sufficient, for calling S-01 proven. The generated set is *more* controlled than the originals, which cuts both ways: exact ground truth, but exactly one generator's idea of a scan.
- **Geometry export must not change fixture bytes, and the mask must not be resampled.** Splitting the distortion chain into geometric and photometric halves is the load-bearing assumption of Phase 3 — and that split does not exist cleanly in the code today (`fold` is both). Byte-identity and an identity round-trip are both explicit criteria because a subtly-biased oracle would let every downstream assertion report green while being wrong.
- **Polish diacritic accuracy is unverified on these specific scans.** `9.png` exists for exactly this and directly affects FR-005's exact-match assumption in S-02.
- **PESEL search has no linguistic redundancy.** A single misread digit yields a confident zero-match with no hint why — the one field where OCR error is least recoverable, and the reason the checksum is retained as evidence rather than discarded.
- **`1.png`–`6.png` are second-class and will stay that way.** No PESEL column, no signatures, no ground truth, and not regenerable. They are kept as the only non-script samples, with their limits recorded rather than papered over.
- **`paddlepaddle` is heavy to freeze with PyInstaller** — the known regression, deferred to `release.yml` and the ONNX export path.

## Success Criteria (Summary)

- A user points the tool at any of the 26 fixtures and sees the correct number of correctly-reconstructed rows — including the degenerate pages (0 rows, 1 row, two tables, 26 rows running off the bottom edge) — with uncertain OCR visibly marked rather than silently trusted.
- The drawn overlay confirms row bands sit on true row boundaries, following the wave on `11.png` and the borderless columns on `16.png`.
- Column roles are named per document across all three layouts, so S-02 can implement `--field imie|nazwisko|imie-nazwisko|pesel` without re-deriving geometry.
- The source file is provably untouched and the working tree carries no stray artifacts, on every path including failure and interrupt.
